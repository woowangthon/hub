# 프로젝트 아카이빙 자료 제출 안내

- 필수 제출물 중 **아카이빙 자료** 제출 방법을 위한 안내입니다.
- 프로젝트를 처음 접하는 사람도 해결하려는 문제와 주요 기능을 이해할 수 있도록 작성해 주세요.
- 아카이빙 자료는 **모든 팀의 필수 제출물**이며, 제출한 내용은 외부에 공개됩니다.
- 자료 자체의 디자인이나 완성도는 별도로 채점하지 않습니다.

## 1. 제출 파일 준비하기

- `main`에서 본인 팀의 브랜치를 만드세요.
- 브랜치 이름은 `W01`~`W51`이며, 1팀은 `W01`, 32팀은 `W32`입니다.
- 참가자는 본인 팀 브랜치의 `archive/` 안에 있는 제출 자료만 수정해 주세요.

```text
archive/
├─ README.md
├─ archive.json          # 여기에 실제 제출 내용을 작성
├─ archive.example.json  # 작성 참고용 예시
└─ screenshots/          # 추가 화면 이미지를 넣을 폴더
```

- `archive.json`에 우리 팀의 정보로 기입하세요.
- 대표 이미지는 `archive/`, 추가 화면 이미지는 `archive/screenshots/`에 넣어 주세요.

## 2. 프로젝트 정보 작성하기

- 필드 이름은 그대로 두고 값을 수정하세요.
- **`demoUrl`만 선택 항목이며, 나머지 항목은 모두 필수입니다.**
- 필수 항목은 빈 문자열이나 빈 배열로 제출할 수 없습니다.

| 필드 | 작성할 내용 |
| --- | --- |
| `teamNumber` | 운영진이 안내한 팀 번호. `W01`은 숫자 `1`, `W32`는 숫자 `32`로 작성 |
| `teamName` | 팀 이름 |
| `title` | 프로젝트 이름 |
| `summary` | 프로젝트를 소개하는 한 문장 |
| `problem` | 해결하려는 문제와 그 문제가 중요한 이유 |
| `targetUsers` | 프로젝트를 사용할 주요 대상. 배열로 작성 |
| `features` | 실제로 구현한 주요 기능. 배열로 작성 |
| `techHighlights` | 기술 선택 이유, 주요 처리 방식, 직접 구현한 부분 등 기술적 특징. 배열로 1~3개 권장 |
| `techStack` | 프로젝트에 사용한 기술. 배열로 작성 |
| `repositoryUrl` | 프로젝트 소스가 있는 대표 공개 GitHub 저장소의 HTTPS 주소, 여러 개라면 택1 |
| `demoUrl` | 서비스 접속 또는 앱 접근/설치용 HTTPS 주소. 없으면 빈 문자열(`""`)로 두거나 항목 생략 |
| `demoVideoUrl` | 시연 영상으로 제출한 YouTube HTTPS 주소. 공개 또는 일부 공개로 설정 |
| `thumbnail` | 대표 이미지의 상대 경로. 예: `thumbnail.png` |
| `screenshots` | 추가 화면 이미지의 상대 경로 배열. 예: `["screenshots/screen-1.png"]` |
| `members` | 모든 팀원의 이름, 담당 역할, 기여 내용 |

### 팀원 소개 예시

- `members` 배열 안에 팀원별 정보를 작성하세요.
- 한 사람이 여러 역할을 담당했다면 `roles`에 함께 넣어 주세요.
- 이 자료는 공개되므로 전화번호, 이메일, 비밀번호, API 키 등 개인정보나 비밀정보는 넣지 마세요.

```json
{
  "name": "홍길동",
  "roles": ["프론트엔드", "디자인"],
  "contribution": "프로젝트 검색과 상세 화면 구현"
}
```

## 3. 이미지와 링크 확인하기

- 이미지 경로는 `archive.json`이 있는 폴더를 기준으로 작성하세요.
- 예를 들어 `archive/thumbnail.png`를 추가했다면 JSON에는 `thumbnail.png`로 적습니다.
- 추가 화면은 `screenshots/screen-1.png`처럼 작성합니다.
- PNG, JPEG, WebP 형식의 정적 이미지를 사용할 수 있습니다.
- 이미지 비율은 자유이며, 화면의 글자와 기능을 알아볼 수 있는 이미지를 제출해 주세요.
- 파일 확장자는 실제 이미지 형식과 같아야 합니다.
- 외부 이미지 URL이나 `../`처럼 폴더 밖을 가리키는 경로는 사용할 수 없습니다.
- 심볼릭 링크, 서브모듈, 실행 파일은 제출할 수 없습니다.

| 항목 | 최대 크기 |
| --- | --- |
| 이미지 한 장 | 20MiB, 4천만 픽셀 |
| `archive/` 폴더 전체 | 100MiB |
| `archive.json` | 100KiB |


## 4. 제출 후 결과 확인하기

1. 작성한 JSON과 이미지를 본인 팀 브랜치(`W01`~`W51`)에 커밋하고 푸시하세요. **PR 생성이나 `main`으로의 머지는 필요 없습니다.**
2. GitHub의 **Actions → Archive Automatic Deployment → Validate Archive Submission**에서 검사 결과를 확인하세요.
3. 검사에 실패했다면 오류 메시지에 표시된 필드나 파일을 수정하고 다시 푸시하세요.

---
제출과 관련된 문의는 디스코드 `질문-문의` 채널을 이용해주세요.
