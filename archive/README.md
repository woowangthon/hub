# 작품 제출 양식

`archive.example.json`은 작성 참고용입니다. 내용을 빈 `archive.json`에 복사한 뒤 우리 팀의 정보로 수정하세요.
제출 검사는 **archive.json**을 읽습니다. 예시 파일만 수정하거나 제출 파일을 비워 두면 제출되지 않습니다.

**demoUrl만 선택 항목이며, 나머지 항목은 모두 필수입니다.**

## 1. 작품 정보 작성

필드 이름은 그대로 두고 값을 수정하세요.

| 필드 | 작성할 내용 |
| --- | --- |
| teamNumber | 팀 번호. W01은 숫자 1, W32는 숫자 32 |
| teamName | 팀 이름 |
| title | 작품 이름 |
| summary | 작품을 소개하는 한 문장 |
| problem | 해결하려는 문제 |
| targetUsers | 주요 사용자를 배열로 작성 |
| features | 주요 기능을 배열로 작성 |
| techHighlights | 기술적 특징을 배열로 작성. 1~3개 권장 |
| techStack | 사용 기술을 배열로 작성 |
| repositoryUrl | 작품 소스가 있는 대표 GitHub 저장소의 HTTPS 주소 |
| demoUrl | 서비스 접속 주소. 없으면 빈 문자열(`""`)로 두거나 항목 삭제 |
| demoVideoUrl | 누구나 재생할 수 있는 HTTPS 시연 영상 주소 |
| thumbnail | 대표 이미지의 파일 경로. 예: `thumbnail.png` |
| screenshots | 추가 화면의 파일 경로 배열. 예: `["screenshots/screen-1.png"]` |
| members | 팀원별 이름, 담당 역할, 기여 내용 |

필수 항목은 빈 문자열이나 빈 배열로 제출할 수 없습니다.

### 팀원 소개 작성 예시

`members` 배열 안에 팀원별 정보를 넣으세요.

```json
{
  "name": "홍길동",
  "roles": ["프론트엔드", "디자인"],
  "contribution": "작품 목록과 상세 화면 구현"
}
```

모든 팀원의 이름, 담당 역할, 기여 내용을 작성하세요.
전화번호나 이메일 등 추가 개인정보는 넣지 마세요.

## 2. 이미지 넣기

- 예시 이미지는 제공하지 않습니다. 대표 이미지는 `archive/`, 추가 화면은 `archive/screenshots/`에 직접 넣으세요.
- JSON에는 `archive.json`을 기준으로 경로를 작성하세요.
  - 대표 이미지: `thumbnail.png`
  - 추가 화면: `screenshots/screen-1.png`
- PNG, JPEG, WebP 형식의 정적 이미지를 사용할 수 있습니다.
- 파일 확장자는 실제 이미지 형식과 같아야 합니다.
- 이미지 비율은 자유입니다.

| 항목 | 최대 크기 |
| --- | --- |
| 이미지 한 장 | 20MiB, 4천만 픽셀 |
| archive 폴더 전체 | 100MiB |
| archive.json | 100KiB |

외부 이미지 URL이나 `../`처럼 폴더 밖을 가리키는 경로는 사용할 수 없습니다.
심볼릭 링크, 서브모듈, 실행 파일도 제출할 수 없습니다.

## 3. 제출하고 결과 확인하기

1. 본인 팀 브랜치(`W01`~`W51`)에 커밋하고 푸시하세요.
2. GitHub의 **Actions → 전시회 자동 배포 → 제출 JSON·이미지 검사**를 확인하세요.
3. 검사에 실패하면 오류 메시지에 표시된 항목을 수정하고 다시 푸시하세요.

검사를 통과해도 사이트에 즉시 표시되지는 않습니다.
정기 반영은 매일 한국 시간 00:10에 시작하며, 실행 상황에 따라 지연될 수 있습니다.
